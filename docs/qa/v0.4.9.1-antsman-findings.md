### Draft blocker (not a verdict)

**A held scrub keeps "LIVE" in the trend header after the data has turned STALE.** While a finger or mouse button is held, `buoyCardBusy()` defers the card repaint, so the trend header stays frozen. Reproduced at 390 touch and 1440 mouse:

- H9c: refresh fails during the hold; header still says "48 h TREND · LIVE · … pulled 1m ago".
- H9d: pull ages past 50 min during the hold; header still says "LIVE · … pulled 49m ago".
- It flips to STALE only on release. The hold can last as long as the user likes, so the card can label STALE data as LIVE for that time.

Ops' scrub R1 did not hold across a STALE transition, so their 212/212 could not catch this. Draft suggestion: while busy, keep the drawn rows deferred but update the `.bhs` state badge and pull-age text in place, and add a hold-through-STALE test.

## Follow-up on this rebase (v0.4.12, after PR #6 was retargeted to main)

On 27 Nov 2026, DoubleA approved a fix for the draft STALE-during-hold blocker. While a scrub is held, `buoySurfaces` now updates the `.bhs` trend header (status + pull age) and the card title LIVE|STALE in place, without rebuilding the card or moving the readout, ring, or line. The header age keeps counting during the hold, and the header flips LIVE→STALE as soon as the data is stale — it does not wait for release. "Catches up on release" is not the passing behavior.

This addresses the provisional H9c/H9d blocker in code, pending Lil Ant's live verification on the hosted preview of this build. It does not close Antsman's unfinished R2 check, is not a brief-check verdict, and this PR still does not claim VERIFIED.

A later preview check of 82050ac found the BUOY card would not open at all: `buoyHistLastDrawn` was assigned in the history-draw path but never declared, and the script is strict mode, so `buoyOpenCard` threw before render. That binding is now declared. Live v0.4.11 does not use it and was unaffected. `buoySparkScale` remains in this branch for the scrub readout/ring/line; it is not a live sparkline fix (production inlines the scale in `buoySpark` and already draws fine).
