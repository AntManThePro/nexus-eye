## What this PR changes (client)

- TREND sparklines become scrub-able: hover reads, click/tap pins, ←/→/Home/End step, Escape or the ✕ clears. Touch uses an 8 px axis lock (sideways scrubs, vertical scrolls the card and does not pin).
- Readout, ring and line come from the series snapshot already drawn on the card (`buoyHistLastDrawn` / `tip.__buoyDrawn`), never a newer undrawn pull. Gaps are jumped, not interpolated. `role="slider"` + ARIA. OLD OBS is carried in the readout.
- Staging's idle-drift hold (`&&!buoyScrubActive()`) is not applied because live v0.4.6 already removed idle drift. The globe stays still when untouched.
- Follow-up (same version, after PR #6 was retargeted to main): while `buoyCardBusy()` is true, `buoySurfaces` updates the `.bhs` TREND header (status + pull age) and the card title LIVE|STALE in place, using `buoyHistStatus` / `buoyStationStatus`. It does not rebuild the card `innerHTML` or move the scrub readout, ring, or line. The header age keeps counting during the hold and flips LIVE→STALE the moment the data is stale — it does not wait for release.
- The honesty follow-up also introduces `buoySparkScale` so the v0.4.12 scrub readout, ring and line can share the sparkline's scale math. Live v0.4.11 already draws sparklines fine: it inlines that math inside `buoySpark`. This helper is for the #6 scrub readout, not a production sparkline fix.
- Follow-up (card-open blocker, after Lil Ant's preview check of 82050ac): `buoyHistLastDrawn` was assigned in the history-draw path but never declared. The page script is `'use strict'`, so opening a BUOY card threw `ReferenceError` before render. Declared `let buoyHistLastDrawn=null;` next to the other buoy-hist state. Live v0.4.11 does not use this binding and was unaffected. An eslint `no-undef` sweep of the v0.4.12 script vs main found no other undeclared assignment that strict mode would throw on (`typeof layerFreshness` is an intentional safe guard already on main; `buoyCardBusy` is a `window` property, also already on main).
