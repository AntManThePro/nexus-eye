# v0.4.7 local function tests

Ran on the builder box, Friday Nov 27, 2026, 4:26 AM CT. Handlers invoked directly with Node 24 (`export default` + Web `Request`/`Response`), against the real upstreams. No Netlify deploy. `netlify dev` was not required.

## `/api/air` (`netlify/functions/air.js`, Texas-first adsb.lol)

- First call: HTTP 200 in 1812 ms. `x-nexus-eye: air-v0.4.7`. `ok: true`, `stale: false`, `source: "adsb.lol"`, `cached: false`.
- 6/6 regions answered (`partial: false`). 169 aircraft after the per-region cap. 25 of those sat in a Texas bounding box (lat 25–37, lon −107 to −93). The first three rows were Texas-region flights: BVN8278, UAL505, NASH66.
- Second call (in-memory cache): HTTP 200 in 0 ms, `cached: true`, same count and source time.

This is the path live v0.4.6 still fails: production `/api/air` (`air-v0.3`, OpenSky) returned HTTP 503 `fetch failed` when checked Nov 26, 11:46 PM CT.

## `/api/fire` (`netlify/functions/fire.js`, NASA FIRMS MODIS C6.1)

- First call: HTTP 200 in 180 ms. `x-nexus-eye: fire-v0.4.7`. `ok: true`, `source: "firms-modis-c6.1"`, `window: "24h"`, 800 hotspots (the function's thin cap), `cached: false`. Rows have `lat`, `lon`, `frp`, `sat`, `dn`, `date`, `time`, `conf` — the shape the v0.4.6 FIRE client already expects.
- Second call: HTTP 200 in 2 ms, `cached: true`.

Live `/api/fire` returned HTTP 404 at Nov 26, 11:50 PM CT because this function was not on the production site or in `origin/main`.
